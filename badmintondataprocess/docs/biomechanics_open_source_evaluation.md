# BBA 骨骼动作细节分析：开源方案评估与迁移路线

更新时间：2026-09-01

## 1. 结论

BBA 不应直接接入一个通用动作识别模型后就宣称完成“动作分析”。现有开源成果最适合拆成四条相互独立、可验证的数据链：

1. **击球事件定位**：先确定可能的击球帧、击球者和证据强度。
2. **击球类型分类**：对事件窗口运行羽毛球专项模型。
3. **二维运动学计算**：从 RTMPose 的逐帧 COCO-17 骨骼计算关节角、角速度和身体稳定性描述。
4. **步法与恢复分析**：结合脚踝、球场米制位置和击球事件分析启动、制动、跨步与回位。

推荐的开源组合是：

- **BST（主分类器）**：作为击球类型分类的第一选择。
- **Sports2D（角度计算参考）**：迁移二维关节和身体节段角度的定义、过滤思想与输出口径，不重复运行它的姿态检测。
- **RacketVision（后续增强）**：在第二阶段增加球拍检测和五关键点姿态，提高击球手判断、挥拍方向和接触证据质量。
- **ShuttleSet / BFMD（训练与验证数据）**：用于击球事件和类型的监督，不把训练集表现直接当成本项目效果。

TemPose 可以保留为分类基线，但不建议作为新的主分类器；通用 MMAction2、MotionBERT 和 OpenCap 不进入第一版生产管线。

## 2. 与 BBA 现有数据的匹配程度

BBA 已经具备：

- RTMPose 输出的逐帧 COCO-17 二维关键点及置信度；
- `near` / `far` 场地角色与逐回合轨迹；
- 经验证 Homography 得到的球员米制场地位置；
- TrackNet 羽毛球图像轨迹及 `observed / interpolated / missing` 状态；
- 可用回合、原视频帧区间、阶段产物和质量门槛。

BST 的输入正是双人 COCO-17 骨骼、球员场地位置和羽毛球轨迹，因此数据形态高度匹配。BST 官方实现要求先把每次击球裁成定长时序窗口，并按训练约定归一化：骨骼相对球员框、球位置相对视频尺寸、球员位置相对标准球场。

当前真正缺失的不是姿态模型，而是以下中间层：

- 可靠的击球帧与击球者；
- 事件窗口内连续且同帧对齐的双人骨骼、球员位置和羽毛球轨迹；
- 持拍手判断；
- 面向远端小人物的动作分析资格门槛；
- 可与人工标注对比的冻结测试集。

因此不能直接把现有 `reversal_candidate` 当成已确认击球。它只能作为事件候选证据之一。

## 3. 候选项目评估

### 3.1 BST — 推荐直接迁移

项目：<https://github.com/Va6lue/BST-Badminton-Stroke-type-Transformer>

许可证：MIT（代码可兼容迁移，但仍需单独核对所下载模型权重和数据集的分发条款）。

优点：

- 羽毛球专项，而不是 NTU 等日常动作预训练标签；
- 官方提供推理入口和 ShuttleSet、BadmintonDB、TenniSet 权重；
- 同时消费骨骼、羽毛球轨迹和场地位置；
- 支持 COCO-17 和二维输入；
- 提供 25 类合并标签，可进一步映射为 BBA 面向用户的较粗类别；
- 论文在 ShuttleSet 25 类设置下报告约 0.83 accuracy，并明确指出球轨迹信息有价值。

迁移注意：

- 官方推理样例读取已经整理好的 `.npy` 数据，不是完整长视频接口；
- 模型依赖准确的击球中心窗口，事件定位错误会先于分类器造成失败；
- 25 类对普通用户过细，应同时输出原始类别、合并类别、Top-2 和置信度；
- 官方类别把 Top / Bottom 编进标签，BBA 应将场地角色与动作类别拆开保存；
- 不满足输入覆盖率或置信度时输出 `not_eligible`，不能强制给出类别。

### 3.2 TemPose — 保留为研究基线

项目：<https://github.com/MagnusPetersenIbh/TemPose-BadmintonActionRecognition>

许可证：MIT。

优点：

- 输入同样是双人、17 关节时序；
- 模型规模较小；
- 在论文使用的 Badminton Olympics 数据上有较好的已发表结果。

不足：

- 类别体系较旧且较粗；
- 仓库更偏训练研究代码，开箱推理和权重交付不如 BST 完整；
- 没有利用 BBA 已经具备的完整球路与场地上下文达到 BST 的程度。

结论：作为离线对照模型或消融实验，不作为首个生产分类器。

### 3.3 Sports2D — 推荐迁移二维角度定义

项目：<https://github.com/davidpagnon/Sports2D>

许可证：BSD-3-Clause。

可迁移内容：

- 肩、肘、髋、膝等二维关节角定义；
- 身体节段角度定义；
- 低置信关键点拒绝、短缺口处理、异常值过滤和平滑的思路；
- 输出原始值和处理值并保留质量信息的方式。

不建议整套接入。BBA 已经运行 RTMPose、角色跟踪和视频解码；再次运行 Sports2D 会重复计算并造成身份与帧号不一致。应在 BBA 内建立小型、纯函数化的 `kinematics` 模块，直接消费已有姿态 CSV。

能力边界：Sports2D 官方明确说明，二维角度只有在运动主要位于拍摄平面内时才较可信。羽毛球转播画面含明显透视和出平面旋转，因此报告必须称为“二维投影角度”，不能称为三维关节角或医学级生物力学结论。

### 3.4 RacketVision — 推荐作为第二阶段增强

项目：<https://github.com/OrcustD/RacketVision>

许可证：MIT。

价值：

- 提供球拍检测和五关键点球拍姿态；
- 有预训练权重下载入口；
- 可以补足 COCO-17 不包含球拍、手指和持拍方向的根本缺口；
- 可把“手腕高速运动 + 羽毛球反转”升级为“球拍头接近羽毛球 + 轨迹变化”的更强接触证据。

风险：

- 依赖 MMDetection / MMPose / MMCV，可能与当前轻量 `rtmlib + onnxruntime` 环境冲突；
- 远端球拍目标很小，必须单独验证；
- 第一版可以设计插件接口，不应立即加入默认安装和主流程耗时。

### 3.5 MMAction2 — 只采用框架思想

项目：<https://github.com/open-mmlab/mmaction2>

许可证：Apache-2.0。

MMAction2 提供 PoseC3D、ST-GCN、STGCN++ 等成熟骨骼动作识别框架，但其公开预训练标签不是羽毛球击球类型。直接用 NTU 权重不会得到“杀球、吊球、挑球”等结果。若未来需要统一训练平台，可以把 BBA 导出的事件窗口适配为 MMAction2 自定义数据集；首版没有必要引入整套依赖。

### 3.6 ShuttleSet、BFMD 与其他数据

- **ShuttleSet**：44 场专业单打、逐拍类型和击球方等标注，适合训练击球事件和类型模型。必须按比赛划分训练/验证/测试，不能把同一场视频切片后随机混入不同集合。
- **BFMD**：包含逐拍击球帧、击球类型、球轨迹和球员姿态，可用于跨年份、跨赛事验证，也包含双打样本。
- **MultiSenseBadminton**：含可穿戴传感器、足底压力和动作水平标签，适合研究真正的稳定性与技术质量，但与单目转播视频的数据模态不同，不能直接训练 BBA 的视频评分器。
- **Fine-Badminton**：适合未来研究长视频中的精细时序动作定位，但需要单独核对数据许可、标注格式和与现有类别的映射。

## 4. 不直接迁移的项目

- **ShuttleScope**：其手腕速度、肘角与三级击球者归属思路值得参考，但仓库采用专有 source-available 许可证，禁止把代码复制进 BBA 或重新分发修改版。
- **BaddieVision、Adapted-HitNet、部分演示型分类仓库**：未发现明确可复用许可证，或者权重/数据未随代码发布；只能作为公开思路线索，不能复制实现。
- **badminton_cv_annotator**：工程与质量门槛做得较完整，但为 LGPL-3.0-or-later，若复用需要保持明确组件边界并履行许可证义务。其公开基线的击球接触 F1 约为 0.62，也说明事件检测尚不能无审核地当真值。
- **MotionBERT / OpenCap / OpenCap Monocular**：可以研究三维姿态或肌骨模型，但转播视频缺少受控相机、人体尺寸和校准动作。第一版引入会放大伪精确风险。
- **基于单帧模板或固定角度阈值的“AI 教练”项目**：可以参考交互方式，但不足以验证连续比赛中的击球分类和技术评分。

## 5. 推荐架构

```text
RTMPose player observations -----+
                                 |
TrackNet observed shuttle -------+--> Stroke Event Spotter
                                 |      - candidate frame
Validated court positions -------+      - candidate player
                                        - evidence + confidence
                                                  |
                                                  v
                                      Event Window Builder
                                      - frame alignment
                                      - coverage gate
                                      - normalization
                                        |               |
                                        v               v
                              BST stroke classifier   2-D kinematics
                              - raw class            - joint angles
                              - merged class         - angular velocity
                              - top-2/confidence     - phase boundaries
                                        |               |
                                        +-------+-------+
                                                v
                                     Footwork / stability descriptors
                                     - lunge / split-step candidates
                                     - braking and recovery
                                     - support width / body sway
                                     - eligibility + uncertainty
                                                |
                                                v
                                   CSV/JSON -> WebUI -> annotated video
```

每条结论必须关联：`video_stem`、`rally_id`、`player_id`、原视频帧号/时间、证据来源、输入覆盖率、模型版本和置信度。

## 6. 建议实施顺序

### 阶段 A：动作分析数据契约与二维运动学

不依赖新增模型，先交付可验证基础：

- 新增 `biomechanics_analysis` 独立阶段；
- 输出逐帧二维肩/肘/髋/膝角和有效性；
- 输出逐回合角度范围、左右差异、身体中心摆动、支撑宽度；
- 在 WebUI 中显示“二维投影指标”及资格原因；
- 使用合成骨骼和人工抽帧建立单元测试/视觉验证。

### 阶段 B：击球事件定位

- 将球路反转、球员/球距离、手腕速度、肘角变化和角色边界作为多证据输入；
- 初期只输出 `stroke_candidate`，不沿用含义更强的 `hit`；
- 从 ShuttleSet / BFMD 建立按比赛冻结的事件测试集；
- 达到预先约定的 precision / recall 后才允许生成正式击球窗口；
- 对低视角和远端人物分别报告指标。

### 阶段 C：BST 分类器

- 迁移 MIT 代码并保留第三方声明；
- 编写 BBA CSV 到 BST 张量的适配器，不重复执行姿态、TrackNet 和标定；
- 首先启用 ShuttleSet 25 类合并权重；
- 输出 Top-2、置信度、未知类和不具备分析资格原因；
- 对我们的不同机位样本做域外验证后再默认开启。

### 阶段 D：挥拍阶段

第一版阶段边界采用事件中心的可解释时序信号：

- 准备：持拍侧手腕速度开始持续上升前；
- 加速：手腕/前臂角速度显著上升到接触候选；
- 接触：事件检测器给出的窄时间窗，不伪称单帧真值；
- 随挥：接触后角速度下降且手臂继续运动；
- 恢复：身体中心和双脚重新趋向稳定/回位。

阶段边界应带置信区间。缺少持拍手、腕肘关键点或连续帧时整体 `not_eligible`。

### 阶段 E：球拍与技术评价

- 以可选插件接入 RacketVision；
- 用球拍头方向增强接触和挥拍平面判断；
- 在积累人工复核数据前，只给出描述性指标，不给“标准/不标准”总分；
- 稳定性和步法评价需按动作类别、机位、球员侧别分别验证。

## 7. 第一版明确不承诺的内容

- 不从单目转播视频输出医学级三维关节角、关节力矩或伤病风险诊断；
- 不把球员框内的二维身体中心称为真实人体质心；
- 不把羽毛球图像轨迹反转自动等同为真实击球；
- 不在无法判断持拍手时强行区分正手/反手；
- 不用职业球员的单个角度模板给普通用户打绝对技术分；
- 不把训练数据集上的论文准确率当作 BBA 上传视频的实际准确率。

## 8. 下一步决策

建议按“阶段 A -> 阶段 B -> 阶段 C”推进。阶段 A 可以立即利用现有产物实现；阶段 B 决定后续分类器上限；阶段 C 才接入 BST 权重。这样即使分类模型尚未上线，报告也能先从“开发中”升级为有质量门槛的二维运动学分析，而不会把未经验证的启发式结果包装成完整动作评价。
